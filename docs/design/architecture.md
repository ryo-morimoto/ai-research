# 設計：全体像

（現在形。経緯・計測・採らなかった案は adr/archive/02 の §8 と §7.8。部品ごとの詳細は同じディレクトリの各ファイル）

## 要旨

1. **調査の道具・記憶・手順は、利用者の Cloudflare 上の「ハブ」1か所に置き、リモート MCP で公開する。** claude.ai に1回登録すれば、どの PC・スマートフォンからも同じハブに届く（Q-05、U-01）。
2. **モデルの判断は、依頼を受けた会話の Claude がする。** ハブは LLM を呼ばない。
3. **会話の Claude は、ハブの道具を呼ぶ短いコードを書くだけ（code mode）。** 検索・取得・抽出・照合・段落選びはハブの隔離された実行環境で進み、会話に戻るのは上限つきの束だけ（S-01、S-05、R-01）。
4. **手順と常設の方針は、ハブの道具そのもの（関数と説明文）に入れる**（Q-05、Q-06）。
5. **台帳には出典と原文の短い抜き書きだけ。** 書き込みは照合器経由のみ（Q-01〜Q-03、E-01）。
6. **経路に乗せる部品（スキル・フック）は1つのプラグインにまとめ、アカウントに登録する。** 止めるかどうかの判断はハブが持ち、届かなければ止めない（U-03、Q-07）。

## 設計原則（D1〜D15 の要約）

- 道具と記憶は1か所（D1）。重い作業はコードの中、会話には小さな束だけ（D2）。手順は道具に埋め込む（D3）。
- 持ち込むのは証拠だけ（D4）。主張は段落に縛る（D5）。締め切りは道具の側（D6）。
- 経路は、できる面では強制し、できない面では常に読まれる場所で指示し、どちらも測る（D7）。経路の判断もハブに置く（D8）。
- 依頼の種類（D9）・原文の塊（D10）・出典の種類（D13）はデータで持つ。説明は内容ごとに1か所（D11）。失敗は境界で型にする（D12）。関連は絶対の下限も持つ（D14）。終わりは作業の状態で決める（D15）。

## 機械ごとに分かれていないことの棚卸し（Q-05）

| 項目 | どこにあるか |
|---|---|
| 持ち込める事実 | ハブの台帳だけ |
| 調査の手順 | ハブの関数と道具の説明文だけ |
| 道具とその版 | ハブの Worker だけ |
| 取得の条件 | ハブの出口と頻度制限だけ |
| 常設の方針 | policy パッケージ |
| 会話で使うモデル | 各会話（揺らぎとして扱う） |

## 劣化したときの動き

| 状況 | 動き |
|---|---|
| ハブに届かない | フックは止めない側に倒れ、組み込みの道具で調べる。すべて「未照合」＋「届かなかった」と明記 |
| 取得先が拒む | 打ち切り（cutoffs）。URL に DOI があれば書誌・抄録 API で読み直す |
| 予算の上限 | 束を返さず止めて知らせる（budget_stopped） |
| コードの失敗 | 境界で HubError（種別・再試行の可否・次の手）に直す（P-05） |
| 0件 | 理由（no_hits / search_failed / all_failed / not_relevant / still_running）と次の手を通知で返す |

## 会話の流れ（目標値）

依頼 → ターン1: 解釈した問い＋検索語で `research.start`（lookup 15秒 / survey 25秒で束）→ ターン2: 束の段落だけから主張を書き `verify`＋`next` → ターン3: 結果（解釈した問い・主張と状態・出典・打ち切り）。会話の長さによらず3ターン（S-05）。
