# 設計：経路（RouteDO・フック・プラグイン）

（現在形。面ごとの違いと採らなかった案は adr/archive/02 §7.4〜7.8、フックの最小化は §8.3.6）

## 方針（U-03、Q-07、D7/D8）

経路は、止められる面（Claude Code・Cowork）ではフックで強制し、止められない面（チャット）では常に読まれる指示（スキル・アカウントの指示）で導く。判断はハブ（RouteDO）が持ち、**ハブに届かなければ止めない側に倒れる**。

## 登録はアカウントに3つだけ（U-01）

カスタムコネクタ（ハブの MCP）、プラグイン `ai-research`（スキル＋ http フック）、Instructions for Claude の1行。機械には何も入れない。

## フック

| フック | 対象 | ハブがすること |
|---|---|---|
| PreToolUse | WebSearch / WebFetch | 下の規則で止める・通す |
| UserPromptSubmit | すべて | 「明示」の判定（否定の言い方は明示でない。根拠を記録）。プラグインの版の検知（U-05） |
| PostToolUse | ToolSearch だけ（E-05） | コネクタが見つからない会話を期限つきで記憶 |

PreToolUse の規則（上から）：(1) 明示 → 通す＋「経路外（利用者の指定）」、(2) ai-research で取れなかった URL（cutoffAllowReasons のもの）→ 通す＋「経路外（取れなかった）」、(3) 検索が使えなかった（10分）→ 通す、(4) コネクタが見つからない会話 → 通す、(5) それ以外 → 止めて code の呼び方を返す（ROUTE_DENY_REASON）。

## RouteDO が覚えるもの（期限つき）

会話ごとの明示の印（1時間）、取れなかった URL（30分）、コネクタ不在の印（1時間）、検索不能の印（10分）、判断の回数（route_stats）。台帳には触れない。依頼文は保存しない。

## 表示（Q-07）

経路外の結果には「経路外（理由）」を書き、確認済の印は付けず台帳にも入れない。文言の正は policy（ROUTE_DENY_REASON / ROUTE_ALLOW_CONTEXT）。
