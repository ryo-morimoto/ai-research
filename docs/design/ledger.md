# 設計：台帳（LedgerDO）と照合器

（現在形。スキーマの原型は adr/archive/03 §2.4.1、照合の詳細は同 §2.6.2）

## 台帳レコード

出典（種類・正規化 URL・題・位置）、原文そのままの抜き書き（300字まで）、照合用の前後の文脈（各50字）、fingerprint（ETag / Last-Modified / 本文ハッシュ / コミット SHA / arXiv 版）、verified_at、変わりやすさ、書き込んだ実行。**主張・要約・解釈・LLM のタグは持たない**（Q-03）。

- 追記のみ（INV-2）。取り消しは墓標（INV-3、U-02）。records と tombstones は1つの通し番号 seq を共有。
- 実行は開始時の snapshotSeq より後を読まない（INV-4）。
- 全文検索は FTS5 trigram、2文字以下は LIKE に落とす。候補は関連の下限（問いの語の被覆率）と件数の上限で絞る（S-06）。

## 照合器（core/verify）

- `VerifiedExcerpt` は core/verify.ts だけが作れる（ブランド型＋check-deps の規則。INV-1）。台帳の追記はこの型しか受け取らない。
- 抜き書きは、照合で位置が決まった**原文側の文字列**から切り出す。会話の文脈で書き換えた文は原文と一致しないので保存されない（Q-06 の仕組み）。

## 照らし直し（W-03、Q-02）

規則で決め、LLM を使わない：GitHub は最新コミット SHA、arXiv は版番号、Web は条件付き GET と本文ハッシュ、論文は書誌・抄録 API の取り直し、変わりやすいものは常に取得。間に合わなければ「取得できず未照合」、抜き書きが見つからなければ「照合失敗」。決着するまで束に出さない。
